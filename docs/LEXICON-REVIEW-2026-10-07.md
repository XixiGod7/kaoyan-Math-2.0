# 英语词典改造审查与验证记录

日期：2026-10-07。审查基线：`eee27eb2b591baf314d0c6f39c343ffe56efcd5b` 加用户提供的词典统一实现。本次根据“审查代码，测试通过后推送更新”补修、验证；原分析方案保留作历史对照。

## 1. 审查结论与补修

| 问题 | 修复结果 |
| --- | --- |
| 编译器默认可能把兼容词典写回原资料，重复构建丢失来源；空主释义没有采用词频备用义 | 输出默认进入生成目录，拒绝输入输出同目录；保留有效主释义，词频补空并保存异文及来源；编译可重复，摘要稳定 |
| 词频、盲区、精读、题目及生词本仍有独立查词路径 | 通过 `dictionaryService.ts` 共享词条和词频包，组件订阅同一状态；支持主释义及补充义项搜索 |
| 强制重载可重复发请求；重试结果没有传播到全部组件 | 加载和重试共用进行中的请求；失败可重试，生词弹窗内也提供错误及重试入口 |
| manifest、词条、词频版本不一致时静默降级；离线缓存仅含词条 | 校验清单路径、SHA-256 摘要及关联结构；缓存完整同版本包；损坏缓存不作为成功结果；数据库阻塞或写入失败不阻止在线使用，并关闭连接 |
| 查词删除内部标点；词形还原可能覆盖 `used`、`provided` 独立义项 | 共用 `public/shared/lexicon.mjs` 做 Unicode、大小写及首尾标点规范化，保留内部连字符和撇号；精确词优先，歧义还原不猜根；拒绝继承属性作为词条 |
| 批量生词更新使用旧闭包，可能丢掉同批前面的本地排期 | 改用函数式状态更新，逐项基于最新记录合并 |
| 后端复习仍只接受原主词典词；旧大小写变体可能重置排期或重复奖励 | catalog 来自同一次统一编译；规范键提交，保留旧记录的阶段及扩展字段；合并大小写/空白变体时保守判断到期，奖励沿用规范键去重 |
| 数据补全含无法证实的音标、人物履历，且将导入资料描述成已权威核验 | 删除无来源补造；五条专名使用仓库原文上下文；`selfievanity` 明确待审；普通来源标为 imported / supplemented |
| 浏览器验收发现两份来源的音标分隔符不同，生词卡显示双重斜杠 | 统一格式化显示，保留源数据内容 |

统一实现没有重命名所有历史词元，没有全量改写或清空用户的生词、复习阶段、日期、笔记和答案。`english_storage` 与 `english_state` 仍分别承担前端学习状态和服务端学习/奖励记录；本次合并的是公共词条查询来源。

## 4. 浏览器验证与边界

使用隔离本地 Worker 站点进行真实点击验证：

- 词频页检索 `probable`，显示统一中文释义及音标；标为生词后，全词库从 762 增至 763。
- 今日复习卡可以翻面显示同一释义；全词库输入“很可能”能找到该词。
- 构建结束重启模拟服务，在新的本地端口加载后，服务端保存的生词仍可恢复；复习卡的音标只显示一组斜杠。
- 验收截图保存在本机 `artifacts/lexicon-review-probable.jpg`。自动测试覆盖全部 290 个差异词；浏览器只抽查关键流程，没有逐个手工测完 40 词盲区测试或所有题目。

Windows 在构建原子替换静态目录时出现过一次 `EPERM`；正式目录回滚完整，失败的暂存目录可逆归档到 `artifacts` 后完整构建通过。Wrangler 已打开时再次替换目录也会令本地文件监听失效，浏览器可能缓存监听失效期间的错误静态响应；最终页面验收在构建完成后重启模拟服务并使用新的本地端口进行。此问题属于本机开发监听限制，不作为生产部署成功的证据。
